# 米チャレ！ 収支管理（収穫・原価・売上・価格試算）追加 実装依頼

既存の **米チャレ！アプリ（`knak-lab/komechalle`）** に、収支管理の機能を追加する。
あわせて **カモの小屋（`knak-lab/kamo-no-koya`）** から、米チャレ商品の **商品マスタと売上** を受け取れるようにする。

- 依頼日：2026-10-21 ／ 依頼者：kkr
- 置き場所：`komechalle/docs/` に置く。カモの小屋側の作業（A章）は `kamo-no-koya` リポジトリで行う
- 参考資料：レポート「米チャレ収益化×カモの小屋」（2026年度の試算）

---

## 0. いまのアプリ（調査済み・前提）

**米チャレ！（komechalle）**
- React 18 + Vite（**JavaScript・素のCSS `src/styles.css`**。Tailwind・ルーターは無し）／GitHub Pages（Actions、`vars.VITE_GAS_URL`）／GAS + スプレッドシート
- 画面は「つながりマップ」が本体で、カレンダーなどはメニューから開く**ダイアログ**（`src/components/Calendar.jsx`）
- 通信：`src/api.js` の `fetchAll()`（GET `?action=all`）と `call(action, payload)`（POST、`text/plain` で CORS 回避）
- GAS：`gas/Code.gs` の `ACTIONS` オブジェクトで分岐、`sheet_(name, cols)` で列を後ろに足していく方式、`log` シートに変更履歴、`LockService`
- 権限：ログインなし。削除などは**運営モード**（スクリプトプロパティ `ADMIN_KEY` の合言葉）
- `VITE_GAS_URL` 未設定時は**デモモード**（`src/sample.js`、ブラウザ内保存）
- `nodes` に `kind: field`（田んぼ）と `kind: event`（イベント）がある

**カモの小屋（kamo-no-koya）**
- GAS：`gas/Code.gs`（doGet / doPost の switch）、`gas/Sheets.gs`（シート読み書き）。スクリプトプロパティ `API_TOKEN` があれば token 必須
- 商品：シート `商品マスター_原価管理`（`id`=商品名, `name`, `price`, `kind`, `active`, `category`, `baseItemId` …）、カテゴリはシート `商品カテゴリ`
- 売上：シート `売上_Square`（`id`, `日付`, `商品名`, `数量`, `金額(円)`, `unitCostAtSale`, `costSubtotal`, `チャネル`＝Square / BASE）
- 売上の商品名は、フロント（`src/App.jsx` の `resolvedSales`）で **`saleOverrides`（売上個別修正）→ `productAliases`（商品名エイリアス）** の順に解決している

この構成・書き方に**合わせて**追加すること（新しいライブラリや別の仕組みを持ち込まない）。

## A. カモの小屋側：米チャレ向けの読み取り口を追加

### A-1. 対象商品の目印
- `商品カテゴリ` に **「米チャレ」** を追加し、米チャレの商品（焼きおにぎり、おにぎり、お米450g など）をこのカテゴリにする
- 既存のカテゴリ運用を変えたくない場合は、`商品マスター_原価管理` に列 `komechalle`（TRUE/FALSE）を足す方式でもよい。**どちらにするか kkr に確認**

### A-2. 読み取り専用 API
`doGet` に `action=komechalleExport` を追加（`API_TOKEN` の確認は既存どおり）。

```
GET ?action=komechalleExport&token=...&since=2026-09-01
→ {
  ok: true,
  products: [{ id, name, price, category, active }],          // 米チャレ対象のみ
  sales:    [{ id, date, productId, qty, amount, channel }],  // 対象商品の売上のみ、since 以降
  exportedAt: "2026-10-21T05:00:00+09:00"
}
```

- 売上の `productId` は、フロントの `resolvedSales` と**同じ順番で解決してから**返す（`saleOverrides` → `productAliases`）。解決ロジックを GAS 側にも関数として置く
- シートの作成・変更はしない（読み取りのみ）
- 既存の `getAll_()` は重いので使わない

## B. 米チャレ側：収支管理の追加

### B-1. 見せ方と権限
- メニューに **「収支」** ボタンを追加。カレンダーと同じくダイアログ（スマホでは全画面）で開く
- お金の情報なので、**運営モードのときだけ**表示・編集できる
- **収支データは公開の `?action=all` に含めない**。読み込みは POST `call('finance', { adminKey })` で、GAS 側でも `checkAdmin_` を通す
- ダイアログの中はタブで切り替え：**まとめ／収穫／原価／商品／売上／価格試算**
- 上部に年度セレクタ。すべてのタブがその年度の内容になる

### B-2. 管理単位
**年度＝収穫年**（2026年度＝2026年に作付け・収穫したお米）。
売上は日付から年度を自動で決める：**その年度の収穫日以降、翌年度の収穫日より前**の売上はその年度。手動で変えることもできる。

### B-3. シート（`sheet_()` で作成。列は後ろに足していく方式を守る）

**`fin_harvest`（収穫）** ※年度に1行

| fieldIds | f1 | 田んぼ（`nodes` の field）。複数はカンマ区切り、空でも可 |
| areaTan | 1 | 作付面積（反） |
| momiKg | | もみ（未入力可） |
| genmaiBags | 13 | 玄米の袋数 |

**`fin_kamo_products`**：カモの小屋から受け取った商品マスタの写し（`id, name, price, active, syncedAt`）

### B-4. カモの小屋との連携（取り込み）
- komechalle の GAS に `ACTIONS.syncFromKamo` を追加（運営モードのみ）
  - **komechalle の GAS から** `UrlFetchApp` で A-2 の API を呼ぶ。URL と token は komechalle のスクリプトプロパティ `KAMO_API_URL` `KAMO_API_TOKEN` に置く（**画面側のコードには出さない**）
  - 商品マスタは `fin_kamo_products` を上書き
  - 売上は `kamo:<id>` で**重複しないように追加**（何度実行しても同じ結果）。`kamoProductId` で `fin_products` に紐づかない売上は「未紐づけ」として残し、画面で紐づけられるようにする
  - 金額・数量はカモの小屋の値をそのまま使う。**変動費は米チャレ側の `fin_products` の値**を使う（カモの小屋の原価にお米代が入っていると二重に数えるため）
- 画面：収支ダイアログに「カモの小屋から取り込む」ボタンと、最後に取り込んだ日時
- 毎日1回の自動取り込み（GAS の時間主導トリガー）を `setupFinanceTrigger()` で設定できるようにする
- `fin_products` の新規作成時に、`fin_kamo_products` から選んで名前・価格を引き継げるようにする

### B-5. 計算（`src/finance/calc.js` に純関数でまとめる）
```
年度原価        = Σ fin_costs.amount（その年） + Σ その年の償却分
白米kg          = hakumaiKg（実測） ?? genmaiKg × seimaiRate
1kgあたり原価   = 年度原価 ÷ 白米kg
生米g           = riceRawG ?? cookedG ÷ cookRatio
お米原価/単位   = 生米g ÷ 1000 × 1kgあたり原価

お客さま支払額  = price + (customerPaysShipping ? shipping : 0)
手数料          = お客さま支払額 × feeRate + feeFixed（feeRate と feeFixed が 0 なら 0）
変動費/単位     = Σ materials + shipping + 手数料
手残り/単位     = お客さま支払額 − 変動費/単位        ※お米の原価は年度原価で回収する扱い
粗利/単位       = 手残り/単位 − お米原価/単位
損益分岐数量    = ceil(年度原価 ÷ 手残り/単位)

実績の手残り    = Σ (amount − variableCostAtSale × qty)
原価回収率      = 実績の手残り ÷ 年度原価
残りのお米kg    = 白米kg − Σ (qty × riceGAtSale) ÷ 1000
```
- 内部は小数のまま持ち、表示で丸める（円は整数、単価は小数1桁）
- テスト：`vitest` を devDependencies に追加し、`calc.js` だけテストする（C章の値を期待値に）

### B-6. 画面（タブ）
1. **まとめ**：年度原価／白米kg／1kgあたり原価、原価回収の進捗バー（回収後は「黒字◯円」）、残りのお米、商品ごとの「手残り・損益分岐数量・使うお米・収穫に対する割合」一覧、イベントごとの売上（`eventId` 別）
2. **収穫**：もみ・玄米・白米の入力、田んぼの選択、実測／計算の表示
3. **原価**：その年の費用の追加・編集、設備の一覧（何年目か／残り何年）
4. **商品**：販売パターンの追加・編集、カモの小屋の商品との紐づけ。入力中に手残り・損益分岐がその場で変わる
5. **売上**：手入力は日付・商品・数量だけで登録（祭りの最中にスマホで打てること）。イベントはカレンダーの予定から選ぶ。カモの小屋から取り込んだ分は見るだけ（未紐づけの紐づけだけできる）
6. **価格試算**（下の B-7）

### B-7. 価格試算
値段を決めるための計算画面。**保存は必須ではない**（試算だけでも使える）。

- 入力：商品（既存から選ぶか新規）、**値段の候補を最大3つ**、炊いた重さ／生米g、資材・調味料、送料・手数料、**想定の販売数**（1回あたりの数・年間の回数）
- 候補ごとに横並びで表示：
  - 1単位の原価（お米＋資材）と原価率
  - 手残り／粗利
  - 損益分岐数量（その年度の原価を、この商品だけで回収する場合）
  - 想定販売数での1回あたり・年間の手残り
  - **同じ手残りにするのに必要な販売数**（例：250円で80個 ＝ 200円で約104個）
- 参考相場を自由入力でメモできる欄（例：「コンビニおにぎり 160〜200円台」）
- 「この値段で商品に反映」ボタンで `fin_products.price` を更新（運営モードのみ）

### B-8. デモモード
`src/sample.js` に C章の初期データを足し、`VITE_GAS_URL` が無くても収支画面を確認できるようにする（運営モードの合言葉チェックはデモでは通す、既存どおり）。
