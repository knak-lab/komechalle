# 米チャレ！つながりマップ

カモの小屋の姉妹アプリ「米チャレ！」のメンバー名簿です。
顔写真付きのメンバーを、家族・友だち・同僚・ご近所などの線でつないで表示します。

- 画面: React（Vite）。GitHub Pages で公開します
- データ: Google スプレッドシート ＋ Google Apps Script（GAS）
- 写真: カモの小屋アカウントの Google ドライブ（フォルダ ID は `gas/Code.gs` の `FOLDER_ID`）

GAS の URL を設定しないあいだは**デモモード**（架空のサンプルデータ）で動きます。
デモモードの変更は、そのブラウザの中にだけ保存されます。

## しくみ

```
スマホ・パソコン ── GitHub Pages（React の画面）
                      │  読み込み: GET  ?action=all
                      │  保存:     POST {action: ...}
                      ▼
               GAS ウェブアプリ ── スプレッドシート（nodes / edges / log）
                      └─────── Google ドライブ（顔写真）
```

| シート | 中身 |
|---|---|
| `nodes` | 点。`kind` が `member`（メンバー）、`field`（田んぼ）、`event`（イベント）、`skill`（得意なこと） |
| `edges` | 線。`type` が family / partner / friend / colleague / neighbor / intro / work / event / mentor / other / skill |
| `log` | 変更履歴（だれでも編集できるので、何かあったときに戻せるように） |

## はじめての準備

### 1. スプレッドシートと GAS（カモの小屋アカウントで）

1. Google スプレッドシートを新しく作る（名前の例：「米チャレ！名簿」）
2. メニューの「拡張機能」→「Apps Script」を開く
3. `gas/Code.gs` の中身を `コード.gs` に貼りつける
4. 左の「プロジェクトの設定」で「appsscript.json をエディタで表示する」をオンにし、`gas/appsscript.json` の中身を貼りつける
5. 関数 `setup` を選んで「実行」。権限の確認が出たら許可する
   - シート `nodes` `edges` `log` ができます
   - 実行ログに**運営の合言葉**が出ます（スクリプトプロパティ `ADMIN_KEY`。好きな言葉に変えても OK）
6. 「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
7. 表示された URL（末尾が `/exec`）を控える

> `Code.gs` を直したときは「デプロイを管理」→ 鉛筆マーク → バージョン「新バージョン」で更新すると、URL が変わりません。

### 2. 田んぼ・イベントの登録

田んぼとイベントは、運営がスプレッドシートの `nodes` シートに直接書きます（`x` `y` は空欄で OK。アプリが近くに配置します）。

| id | kind | name | size | variety | date |
|---|---|---|---|---|---|
| f1 | field | 上の田んぼ | 12a | コシヒカリ | |
| ev1 | event | 田植え | | | 2026-05-17 |

### 3. 画面の公開（GitHub Pages）

1. GitHub のリポジトリの Settings → Pages → Source を「**GitHub Actions**」にする
2. Settings → Secrets and variables → Actions → **Variables** に `VITE_GAS_URL` を追加し、手順 1-7 の URL を入れる
3. `main` ブランチに push すると自動で公開されます（Actions タブで進み具合が見られます）

## 手元で動かす

```bash
npm install
npm run dev          # デモモードで起動
```

本物のデータにつなぐときは、`.env.example` を `.env.local` にコピーして `VITE_GAS_URL` を書きます。

## カレンダー

メニューの「カレンダー」で、イベント（`kind` が `event` の点）を月ごとに表示します。

- 予定の追加・編集は**運営モード**のときだけ（`time` `place` `note` 列に時間・場所・メモが入ります）
- だれでも予定を開いて、メンバーを選んで「参加する」を押せます。参加はマップのイベントの線（`event`）として保存されます
- 最後に選んだメンバーは、その端末に覚えておきます

## 収支

運営モードのとき、メニューに「収支」が出ます（お金の情報なので、運営モード以外では表示も読み込みもしません。公開の `?action=all` にも入りません）。
年度は**収穫年**（2026年度 = 2026年に作付け・収穫したお米）。売上の年度は収穫日で自動で決まり、売上ごとに手で変えることもできます。

| タブ | 中身 |
|---|---|
| まとめ | 年度の原価・白米・1kgあたり原価、原価の回収、残りのお米、商品ごとの損益分岐、イベントごとの売上 |
| 収穫 | もみ・玄米・白米（実測があれば実測、なければ計算） |
| 原価 | その年の費用と、数年使う設備（年数で割って毎年の原価に入れる） |
| 商品 | 販売パターン（値段・お米の量・資材・送料・手数料）。カモの小屋の商品と紐づけ |
| 売上 | 日付・商品・数量だけで登録。カモの小屋から取り込んだ分と、未紐づけの紐づけ |
| 価格試算 | 値段の候補を3つまで比べる（保存しなくても使える） |

| シート | 中身 |
|---|---|
| `fin_harvest` | 収穫（年度に1行） |
| `fin_costs` / `fin_assets` | その年の費用 / 数年使う設備 |
| `fin_products` | 販売パターン |
| `fin_sales` | 売上（`kamo:` で始まる id はカモの小屋から取り込んだ分） |
| `fin_settings` | `cookRatio`（炊くと何倍か。初期 2.2）、`kamoLastSyncAt`、`priceMemo` |
| `fin_kamo_products` | カモの小屋の米チャレ商品の写し |

計算は `src/finance/calc.js`（`npm test` でテスト）。GAS 側は `gas/Finance.gs`。

### カモの小屋との連携

1. カモの小屋のスプレッドシート `商品マスター_原価管理` の `komechalle` 列を、米チャレの商品だけ `TRUE` にする
2. 米チャレの GAS の「プロジェクトの設定」→「スクリプト プロパティ」に次を足す
   - `KAMO_API_URL`：カモの小屋の GAS ウェブアプリの URL（末尾 `/exec`）
   - `KAMO_API_TOKEN`：カモの小屋のスクリプトプロパティ `API_TOKEN` の値
3. GAS エディタで関数 `setupFinanceTrigger` を一度実行する（毎朝5時ごろに自動で取り込みます。権限の確認が出たら許可）
4. 収支の「カモの小屋から取り込む」でいつでも取り込めます。何度押しても同じ売上が二重に入ることはありません
5. 米チャレの商品と紐づいていない売上は「売上」タブの「未紐づけ」に出るので、商品を選んで紐づけます

変動費（資材・送料・手数料）は米チャレ側の商品の値を使います（カモの小屋の原価にお米代が入っていると二重に数えるため）。

## 使い方のルール（いまの設定）

- URL を知っている人はだれでも見られて、登録・編集・線の追加ができます（ログインなし）
- 線はだれでもつないだり消したりできます（まちがえても、またつなげば OK）
- メンバーや田んぼ・イベントの削除は**運営モード**（合言葉）のときだけできます
- 線はつないだ時点で確定します（承認はいりません）
- 顔の配置はみんなで共有されます。「自動で並べる」はみんなの配置を変えるので、2回押しで実行します
- 変更はすべて `log` シートに残ります
